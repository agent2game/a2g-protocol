## How it works

<Architecture />

<Steps>

1. **Describe the game once.** A [manifest](/glossary/#manifest) lists the world, entity types, what each entity observes and which actions exist.
2. **Ask for decisions.** The game sends observations for a batch of entities and the actions legal right now. The service asks a model to pick one per entity.
3. **Validate and execute.** The game checks each choice and performs it through its own code — or runs its [native AI](/glossary/#native-ai) if there is no valid, fresh decision.
4. **Report back.** The game reports how each decision ended, which becomes the entity's [memory](/glossary/#memory) for its next decision.
5. **Learn and ship** *(proposed)*. Decisions from playtests train a small [local policy](/design/local-policy/). The shipped game runs it offline — no service, no per-decision cost.

</Steps>

## Why A2G

Game AI is usually a hand-written state machine baked into each game. A2G turns plugging a model into that loop into a small, repeatable contract instead of a rewrite.

<CardGrid>
	<Card title="Game stays authoritative" icon="seti:godot">
		Movement, physics, damage and rules stay in the game. The model only picks from actions the game offered.
	</Card>
	<Card title="Fallback by default" icon="approve-check">
		The game's original AI is the default. Timeouts, invalid replies and stale decisions return control to it.
	</Card>
	<Card title="Game-agnostic" icon="list-format">
		The service knows a game only through its manifest. No game logic lives on the AI side.
	</Card>
	<Card title="Observable" icon="magnifier">
		Chosen action, executed state and outcome are reported separately, so you can see what really happened.
	</Card>
	<Card title="Any decision model" icon="random">
		OpenAI Decisions, TypeSafe Jev, a general LLM or a local model — swapped in the service, not in the game.
	</Card>
	<Card title="Ship without the cloud" icon="rocket">
		Proposed: train a small local policy on the model's decisions during development and ship the game with it.
	</Card>
</CardGrid>
